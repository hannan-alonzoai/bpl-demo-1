Colour, typography & components

The reference system behind every screen in BPL Cortex OT: a blue-and-white primary palette, a dark-gray secondary palette, semantic colour rules for vital status and case-stage, and a two-tier typography system built around Sentient for anything clinical, with Sora as the secondary/alternate face.

Semantic colour — vital status

Every clinical reading on screen resolves to exactly one of three states. Colour is the fastest signal a clinician reads, so these three never get reused for anything else in the product.

StateColourTokenWhen to use it
Critical Dark red --critical A vital is outside its safe range badly enough to need attention now (e.g. HR ≤40 severe bradycardia, SpO₂ below threshold, temperature critically low).
Average / typical deviation Orange --typical A vital has drifted from normal but isn't yet dangerous — a borderline or trending reading worth watching.
Normal Blue --normal The default state. Everything reads in blue until it earns a different colour.

Semantic colour — case stage

A separate colour language for workflow/progress state, so it's never confused with clinical urgency. Applied to a step's border and its chip fill together, never colour alone.

StageColourTokenWhen to use it
Completed Light green --completed A step in the process flow (e.g. Positioning, Incision) has already happened.
In progress Light blue --inprogress The current active step, right now.
Upcoming Gray --upcoming Not started yet — deliberately quiet so it doesn't compete with what's active or done.

Alarms

Alarms are shown inline, attached to the room they concern — never in a separate global list the clinician has to go check. That's a deliberate anti-click-count decision: the alarm reaches you at the same moment and in the same place as the room it belongs to, not one navigation step later.

Rule

SignalAlways present?Why
Colour (dark red / orange) Yes Fastest possible read for someone scanning quickly.
⚠ icon Yes Colour alone fails for colour-blind users — the icon is a second, non-colour channel carrying the same "this needs attention" meaning.
Left border accent Yes A third, position-based signal — visible even out of the corner of your eye, before you've read any text.
Plain-language text Yes Never colour/icon only — always says exactly what's wrong ("Low urine output"), no decoding required.

Typography

Sentient is the primary typeface — used for every label, heading and vital number across the clinical product, with tabular figures switched on wherever numerals appear so digits stay aligned as they update. Sora is the secondary option: a drop-in alternative wherever a lighter, more geometric, more generic feel is preferred (e.g. a marketing page, not the live monitor screens).

Primary

Sentient

UI text, headings and vital numerals all in Sentient, with font-variant-numeric: tabular-nums turned on for numbers so figures stay in fixed-width columns. Use this everywhere inside the clinical product.

Human-computer interaction principles

The palette and typography above aren't decoration — each one exists to serve a specific HCI principle, applied because this is a clinical monitoring surface, not a general dashboard.

PrincipleHow it's applied here
Recognition over recallNielsen heuristic #6 Colour + icon tell you a vital's state instantly — no need to remember what "93" means for SpO₂ before deciding whether to worry.
Redundant codingAccessibility / WCAG Every critical signal is colour and icon and position and text, together — never colour alone. Protects colour-blind users specifically, who can't rely on red-vs-blue distinction at all.
Hick's LawFewer choices, faster decisions The highest-priority information (status, alarms) is visible with zero clicks; everything else is one click away at most. No screen ever asks the clinician to choose from a long menu to find something urgent.
Progressive disclosure The carousel shows a summary; clicking a card reveals full vitals and process flow in place — depth is available on demand, but never forced on the default view.
Fitts's LawTarget size vs. speed/error rate Carousel cards, rail entries and tab buttons are sized generously — relevant when a clinician may be gloved, moving quickly, or using a shared touch display.
ConsistencyJakob's Law Blue always means normal, dark red always means critical, everywhere in the product. Meaning learned on one screen transfers to every other screen without re-learning.
Gestalt groupingProximity & common region Patient, procedure and vitals sit inside one bordered card — physically grouping information that belongs together, so the eye doesn't have to hunt across the screen to assemble it.
ChunkingMiller's Law Vitals are split into three labelled groups of ≤6 items (Hemodynamics / Ventilation / Temperature) instead of one long list — matches working-memory limits for scanning under pressure.
Error prevention Tabular figures stop digits from shifting width as values update mid-scan — a genuine patient-safety property, not just a style choice. (Note: Sentient doesn't disambiguate 0/O or 1/l as aggressively as a coding monospace font would — worth a second look if that specific risk matters more than the type choice here.)
Visibility of system statusNielsen heuristic #1 Selected states (active carousel card, active tab, current process-flow step) are always visually distinct, so the clinician always knows exactly what they're looking at.
